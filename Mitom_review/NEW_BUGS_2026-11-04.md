## 明细

### N1 — value-less qualifier 的 `.tbl` 格式
- **位置：** `ncbi_validate.feature_lines`（约 55–61 行）
- **问题：** 对每个 qualifier 一律 `\t\t\t{k}\t{value}`。`/pseudo` 读回为 `['']` 时变成 `\t\t\tpseudo\t`（空值列）。INSDC feature table 无值限定符通常只有 key 列。
- **输入→结果：** P10 后的 GenBank 再 `validate_record` → `.tbl` 含 `pseudo\t`。
- **本机：** table2asn 1.28 仍可能产出 `pseudo TRUE` 的 `.sqn`，但提交用 `.tbl` 不规范。
- **建议（给 Claude Code）：** 无值限定符（`FLAG_QUALIFIERS`）只写 `\t\t\t{k}`。

### N2 — 字面量 `pseudo\tNone`
- **位置：** `mito_curate` P10 设 `qualifiers["pseudo"]=[None]`；`feature_lines` 对 `None` 做 `str(v)` → `"None"`。
- **管道现状：** 提交路径多是 `SeqIO.parse` 磁盘 GenBank（读回 `['']`），故线上常见 N1 而非字面 `None`。但任何对**内存记录**直接 `feature_lines` / 未 round-trip 的路径会写出 `pseudo\tNone`。
- **本机探针：** `feature_lines` + `[None]` → `\t\t\tpseudo\tNone`（已跑）。

### N3 — 分组失败仍合并
- **位置：** `mitom_groups.run_groups`：`merge_outputs(...)` 在检查各组 `rc` **之前**无条件调用。
- **风险：** 一组 OOM/失败、一组成功 → 合并目录混入失败组半成品；总 exit 可能非 0，但用户仍可能拿走 `04.final_gb`。
- **确认：** 造两组、杀一组后再看合并树。

### N4 — Step4 计数吞异常
- **位置：** `mitom_output.finalize_genbank_output` Step4：`except Exception: pass`
- **结果：** 最终 `.gbf` 已写入，但 `pcg/trna/rrna` 可能停在初始 `0` 或旧值 → `annotation-summary.tsv` 误导。

### N5 — 自动分类 blastx 遗传密码写死 5
- **位置：** `mito_classify._blastx`：`"-query_gencode", "5"`
- **风险：** `--clade auto` 用 blastx+密码子投票时，脊椎（2）、被囊（13）等查询框/翻译可能偏，影响门/密码推断。
- **确认：** 同一条 Chordata 序列分别用 gencode 2 与 5 比 HSP/分类结果。

### N6 / N15 — 核基因路径的「假零 ERROR」
- **位置：** `mito_nuc.write_submission`：`subprocess.run(..., check=False)`，若无 `nuc.val` 则 `msgs` 空 → 日志「0 error(s)」。
- **对比：** 比线粒体 `mitom_steps` 好一点（会把 FATAL/REJECT 算进 `err`），但 **工具失败且无产物** 时仍与 Codex R2 同类。

### N7 — intron CM 下载文件名
- **位置：** `mito_intron.subtype_cms` ~560：`SUBTYPE_CM_DIR / it["name"]`，`name` 来自 GitHub API。
- **风险：** `name` 含 `../` 时可写到缓存目录外（早期静态审查已提，本轮确认仍在）。
- **建议：** `Path(name).name`，并限制后缀 `.cm`、拒绝分隔符。

### N8 — 输出锁与 PID 复用
- **位置：** `mitom_pipeline.lock_output`：`os.kill(other, 0)` 判断锁是否存活。
- **风险：** PID 复用后，陈旧锁可能被当成「仍在跑」而永久挡新任务（Linux 少见）。

### N9 — 缺 topology → circular
- **位置：** `mitom_inputs` 收集 GenBank ~333–336：未知/缺失 topology 设为 `circular`。
- **风险：** 短线性 contig（工具省略 LOCUS topology）被当环状处理。

### N10 — transfer_metadata 失败仍成功退出
- **位置：** `mitom_pipeline.workflow_transfer_metadata`：单文件 `except` → `n_fail += 1`，函数末尾仍 `return 0`。
- **结果：** CLI 看起来成功，需读 tsv 才知失败。

### N11 — 非原子 GenBank 写
- **位置：** `mito_curate.py`（`SeqIO.write`）、`mito_core.py`、`mito_nuc.py`、`mito_trna.py`、`mitom_pipeline.py` 等多处；`mito_common.write_gb`（原子 + `/pseudo` 规范化）使用面很窄。
- **风险：** 中断留下截断 `.gbf`；与「半写文件」类审查点一致。
- **附：** `mito_curate` 写 `[None]` 时 Biopython 会写出合法 `/pseudo`；但若某处变成 `['']` 再 `SeqIO.write`，会得到 `/pseudo=""`（`write_gb` 本用来修这个）。

### N12 / N13 — 遗传密码表（再钉）
- `PHYLUM_SYNONYMS["Trematoda"]="Platyhelminthes"` → `PHYLUM_CODE` **9**（吸虫常见 **21**）。
- `Tunicata`→`Chordata`→**2**（被囊动物线粒体常见 **13**）。
- 分类器 `code_of_lineage` 可按参考库纠正一部分，但显式 `--clade`/门默认仍可能错。

### N14 — 复用 `-o` 时清理不全（R9 延伸）
- `clear_previous_work` 只删 `WORK_DIRS` + `06.ncbi_submission` + `work`。
- **不删：** `reports/`、`annotation-summary.tsv`、`all.final.gbf`、比较/作图产物等 → 旧报告/图易混入新跑（与 Codex R9 同族，本机未再全流程复跑）。

## 深度审查追加（D 系列）

来源：[Deep Mitom bug hunt](cb197ae3-dfa0-4451-88b7-9e24e382f7d8)；本机对 Critical / 若干 Important 做了抽查。

### D1 — Critical：被囊动物 import vs run 遗传密码分裂
- **位置：** `mitom_inputs.auto_clade` 用 `PHYLUM_CODE["Chordata"]=2`；`mitom_groups.decide` / `mito_classify.code_of_lineage` → **13**；`mito_tbl.SUBPHYLUM_CODE["Tunicata"]=13`。
- **本机：** 无 `transl_table` 的 Tunicata GenBank → `auto_clade → ('Chordata', 2, …)`，`code_of_lineage → 13`。
- **结果：** `mitom import --clade auto` 与 `mitom run --clade auto` 对同一记录可用不同密码。

### D2 — Critical：intron 路径不支持 exonerate 表 24/33
- **位置：** `mito_core.exonerate_code` 对非内置表生成 64 字母串；`mito_intron.run_exonerate` 写死 `"--geneticcode", str(gencode)`。
- **结果：** code 24/33 时 exonerate 拒表 → 内含子搜索空结果（仅 WARNING），PCG 仍可能由 core 标出。

### D3 — Critical：macOS Miniforge 资源名
- **位置：** `install.sh`：`Miniforge3-${MF_OS}-${MF_ARCH}.sh`，Darwin 时 `MF_OS=Darwin`。
- **官方资产名：** `Miniforge3-MacOSX-…`（非 `Darwin`）→ 无 conda 的 Mac 新装可能 404。

### D4 — Important：CRLF GenBank 分组切割
- **位置：** `mitom_groups._split_input`：`re.split(r"(?m)^//[ \t]*$")` 不匹配 `//\r\n`。
- **本机：** LF → 多块；CRLF → **1 块** → `RuntimeError: N records but 1 '//' blocks`。

### D5 — Important：分类失败回退 Annelida/5
- **位置：** `mitom_groups.decide` + `FALLBACK = ("Annelida-segmented-worms", 5, "")`。
- **结果：** blastx/refs 失败时脊椎等 FASTA 仍可能按环节动物 code 5 跑下去（WARNING）。

### D6 — Important：无 topology 标签当环状
- 与 N9 同族；core `annotate` 对默认 circular 追加 `ORIGIN_EXT`，线性 contig 两端基因可能假 `join`。

### D7 — Important：tRNA 工具失败静默
- `mito_trna` 预测器 `run_tool(..., check=False)`；非零/超时 → 空 stdout → 像「找到 0 个 tRNA」。

### D8 — Important：一切无值限定符 → `\tNone`
- 加强 N1/N2：本机 `ribosomal_slippage=[None]` → `.tbl` 行 `ribosomal_slippage\tNone`。

### D9 — Important：无 CDS → 无 mgcode

### D10 — Important：越界 feature 仍进 `.tbl`

### D11 — Important：`mito_tbl.validate` ≈ R2

### D12 — Important：submission 步 `ok=True`

### D13 / D14 — Important：install.sh 边缘

## 第三轮追加（E 系列）

重点：`mito_ncr` / `mito_engines` / `mitom_inputs` 收集逻辑 / `mito_check`。`run`/`annotate` 会先 `normalize_input` 解压，故 E1 对主流程较轻；对 **未走 normalize 的子命令** 与 **混合目录** 仍重。

### E1 — Important：后缀检查不理 `.gz`
- **位置：** `mitom_inputs._is_fasta_file` / `_is_gb_file` 用 `p.suffix`（`.gz`），不用 `_plain_suffix`。
- **本机：** 仅含 `a.fa.gz` 的目录 → `collect_sequence_files` → `[]`；`iter_inputs` → `FileNotFoundError: No FASTA files`。
- **对比：** `normalize_input` 用魔数+`_plain_suffix`，能解压；主流程先 normalize 则没事。

### E2 — Important：混合目录丢掉压缩 GenBank
- **本机：** 同目录 `x.fa` + `y.gb.gz` → collect 只有 `x.fa`；sniff=`fasta`；`.gb.gz` 静默消失。

### E3 — Important：NCR 说明写进提交表
- **位置：** `ncbi_validate.INTERNAL_NOTE` 只匹配 `check .* manually|mito_\w+\.py`。
- **本机：** NCR note `non-coding region NCR1, … (MitoM)` **原样**进入 `.tbl`。

### E4 — Important：跨原点 feature 的 `span` = hull
- **位置：** `mito_curate.span` = `(start+1, end)`；CompoundLocation 的 start/end 是外接矩形。
- **本机：** 跨原点 NCR `join(951..1000,1..50)` → `span` **(1, 1000)**（整环）。
- **风险：** 对已含 NCR/跨原点 join 的库再跑 `mitom curate` 时，邻域/重叠逻辑被整环 NCR 干扰。流水线顺序是 curate→ncr，同一次 run 较安全。

### E5 — Important：import 时 MitoZ 结果独占
- **位置：** `mito_engines.find_results`：若存在 `*.result/*.gbf`，**只返回 mitoz 列表**，同树其它 `.gb/.gbf` 不导入。

### E6 — Important：MitoZ → 默认 circular
- **位置：** `written_by_mitoz` + `import_results`：MitoZ 写的 `topology=linear.` 被改成 circular。
- **风险：** 线性 contig 当环状注释/旋转；文档要求 `--topology linear`，易漏。

### E7 — Minor：MITOS2 导入 organism=序列名
- `mitos2_record`：`/organism=[rid]`，非物种名 → BankIt/定义行质量差。

### E8 — Minor：`safe_name` 空/符号 → 皆 `NA`
- `safe_name('')` 与 `safe_name('***')` 均为 `NA` → 多样本 id_map/文件名冲突。

### E9 — Minor：check 不见 `.gb.gz`
- `mito_check.gb_files` → `iter_gb_files` 后缀表无 `.gz`；同目录有 `t.gb`+`t.gb.gz` 时只见 `.gb`。

### E10 — Minor：`code_of_lineage` 返回 0
- 空/`Metazoa` only → `0`；若有调用方不做校验，可能把 0 传给注释工具。

### E11 — Important：负链跨原点 → NCR 全灭
- **位置：** `mito_ncr.extent`：负链 join 按转录序 `[high..n, 0..low]` 时得到 `(0, n)`。
- **本机：** `extent=(0,1000)` → `noncoding=[]`（整环被标成已覆盖）。
- **对照：** 部分顺序对调可得约 150 nt 正确弧。

### E12 — Important：import 重名撞车
- `seen[id]>1` → `id_{n}`，若已有真实 `id_2` 则产生重复 ID。

### E13 — Important：accession 用截断 name
- `gb_record_accession`：无 `accessions` 时优先短 `name`（≤16）而非完整 `id` → 元数据对不上。

### E14 — Important：smart 元数据不更新 LOCUS 长度
- exact 匹配会改长度；`smart_resolved` 路径可能留下旧 bp 数。

### E15 — Important：rescue 大小写/别名
- `have` 收集原始 `/gene`；已有 `cox1` 仍可能再加 MITOS 风格 `COX1`。
